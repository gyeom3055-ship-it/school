# 11장. 모바일 UX와 접근성 요구사항

[← 목차로](README.md)

> 요구사항 ID(UX-xx, AC-xx, CP-xx)는 [14장 테스트](09-roadmap-and-tests.md#14-테스트-시나리오와-완료-기준)에서 그대로 참조한다.

## 11.1 화면·해상도

| ID | 요구사항 | 설계 상세 |
|---|---|---|
| UX-01 | 세로 화면 기본 | 스마트폰은 Portrait 고정. 태블릿 가로 화면은 P2 보조 기능(좌우 분할 레이아웃, 방향을 바꿔도 진행 상태 유지) |
| UX-02 | 작은 스마트폰 지원 | 최소 지원 논리 해상도 **360×640dp**. 이 크기에서 글자 크기 100%일 때 문서 필드 값이 한 화면에 최소 6개 보여야 함 |
| UX-03 | 다양한 화면 비율 | 기준 1080×1920(9:16). 9:16 ~ 9:21.5까지 세로로 늘어나는 영역은 **문서 뷰어**가 흡수. 상단 바·판정 패널 높이는 고정 |
| UX-04 | Safe Area | 노치·펀치홀·홈 인디케이터 영역에 버튼 배치 금지. `Screen.safeArea` 기준으로 루트 여백 적용 |
| UX-05 | 태블릿 | 가로폭 600dp 이상이면 콘텐츠 최대 폭 720dp로 중앙 정렬, 비교 모드는 좌우 분할 |
| UX-06 | 프레임 | 목표 60fps, 저사양 기기 최소 30fps. 문서 확대·스크롤 중 끊김 없어야 함 |

**기준 레이아웃 높이 배분 (1920px 기준, 글자 100%)**

| 영역 | 높이 | 비고 |
|---|---|---|
| 상단 바 | 120px | 고정 |
| 요청 카드 | 220~320px | 접기 가능(탭하면 한 줄 요약으로 축소) |
| 문서 뷰어 | 남는 공간 전부 (최소 800px) | 스크롤 |
| 문서 트레이 | 110px | 가로 스크롤 탭 |
| 도구 바 + 근거 트레이 | 230px | 근거가 없으면 트레이 숨김 |
| 판정 패널 | 180px | 고정, 버튼 높이 최소 64dp |

## 11.2 조작

| ID | 요구사항 | 설계 상세 |
|---|---|---|
| UX-10 | 터치·탭 | 모든 핵심 기능은 **탭만으로** 수행 가능해야 함 |
| UX-11 | 스크롤 | 문서 뷰어 세로 스크롤, 문서 트레이·근거 트레이 가로 스크롤. 관성 스크롤 |
| UX-12 | 확대 | 핀치 확대(100~250%), 더블탭(100% ↔ 175%), **⊕/⊖ 버튼**(25% 단위) — 버튼만으로도 모든 배율 접근 가능 |
| UX-13 | 드래그(선택) | 필드를 끌어 다른 필드에 놓아 대조. **대체 조작**: 대조 모드 + 탭 2번 |
| UX-14 | 드래그 없는 대체 | 비교 모드 경계선 조정 → 탭 순환, 바텀 시트 닫기 → ✕ 버튼, 칩 삭제 → ✕ 버튼 |
| UX-15 | 길게 누르기 의존 금지 | 길게 누르기는 *단축 조작*으로만 사용하고, 같은 기능을 버튼으로 반드시 제공 |
| UX-16 | 터치 영역 | 최소 **48×48dp**(Android 권장) / **44×44pt**(iOS 권장) 이상, 인접 터치 영역 간격 8dp 이상. 판정 버튼은 높이 64dp, 버튼 간 간격 12dp |
| UX-17 | 오입력 방지 | 판정은 확인 시트로 한 번 더 확인(기본값). 확인 시트를 끄면 0.4초 입력 쿨다운 |
| UX-18 | 제스처 충돌 | 화면 가장자리 스와이프(iOS 뒤로 가기, Android 제스처 내비게이션)와 겹치지 않도록 화면 좌우 끝 16dp 안에는 드래그 시작 영역을 두지 않음 |
| UX-19 | Android 뒤로 가기 | 열린 시트 닫기 → 모드 해제(대조/표시) → 일시정지 메뉴 순서. 데스크에서 바로 앱 종료하지 않음 |

## 11.3 텍스트와 정보 분할

| ID | 요구사항 | 설계 상세 |
|---|---|---|
| UX-20 | 긴 텍스트 분할 | 해설은 최대 4문장, 한 문단 2문장 이하. 더 길면 "더 알아보기" 접힘 영역 |
| UX-21 | 문서 필드화 | 메일 본문 같은 긴 문서도 의미 단위 필드(보낸 사람/제목/본문 문단/링크/첨부)로 나눠 각각 탭·대조 가능하게 |
| UX-22 | 대화 텍스트 | 도트·선배 대사는 말풍선 1개당 40자 내외, 탭하면 다음 말풍선. "전체 보기"로 한 번에 읽기 가능 |
| UX-23 | 주소 표기 | 이메일·URL은 고정폭 글꼴, 줄바꿈은 `.`·`-`·`/` 뒤에서만 |

## 11.5 문구와 톤 가이드

| 원칙 | 좋은 예 | 피할 예 |
|---|---|---|
| 짧고 쉬운 문장 | "보낸 사람 주소를 확인해 봐요." | "발신자 이메일 주소의 도메인 유효성을 검증하시오." |
| 오답을 생각할 거리로 | "한 번 더 살펴볼까요?" | "틀렸습니다!", "실패" |
| 행동 요령 중심 | "링크 대신 앱에서 직접 확인해요." | "이 링크를 누르면 해킹당해요!" |
| 사람을 탓하지 않기 | "이 메시지는 속이려고 만든 거예요." | "이런 데 속으면 바보예요." |
| 정상 승인 칭찬 | "필요한 일을 할 수 있게 도왔어요!" | (승인 정답에 무반응) |
| 용어 첫 등장 시 설명 | "피싱(믿을 만한 곳인 척 속이는 메시지)" | 설명 없이 "피싱" |
| 존댓말(해요체) 통일 | "~해요", "~볼까요?" | 명령조 "~하라" |

- **어휘 수준**: 초등 5학년이 이해할 수 있는 수준. 한자어·외래어 보안 용어는 [부록 B 용어 사전](10-appendix.md#b-용어-사전)에 등록된 것만 사용하고 첫 등장 시 💡 말풍선으로 설명.
- **금지 표현 목록**(검증 도구 경고 대상): 해킹당, 큰일, 범죄자, 바보, 실패, 망했, 위험해요!, 경고! (해설 본문 기준)

## 11.6 접근성

| ID | 요구사항 | 설계 상세 |
|---|---|---|
| AC-01 | 쉬운 한국어 | 11.5 가이드 준수, 문장 검수 체크리스트 운영 |

| AC-04 | 색각 차이 | 모든 상태는 색 + 아이콘 + 텍스트. 불일치는 빗금 패턴 추가. 흑백 필터 검사 통과 |
| AC-05 | 고대비 모드 | 문서 배경 흰색·글자 검정, 테두리 2배 굵기, 그림자·반투명 제거 |
| AC-06 | 움직임 줄이기 | 이동·확대·흔들림 연출을 페이드 또는 즉시 표시로 대체. 깜빡임은 초당 3회 미만(항상) |
| AC-07 | 읽기 시간 | 자동으로 사라지는 텍스트 없음(토스트 포함, 탭해서 닫기). 시간 도전 모드 외에는 시간 표시 없음 |
| AC-08 | 문서 본문 글꼴 | 도트 테마에서도 문서 본문만 일반 글꼴로 바꾸는 옵션 |
| AC-09 | 소리 의존 금지 | 소리로만 전달되는 정보 없음(모든 효과음에 대응하는 시각 피드백) |
| AC-12 | 전연령 조작 | 차근차근 모드([7.8](04-levels-and-scoring.md#78-플레이-모드-전연령-지원)), 판정 버튼 높이 최소 64dp 유지, 두 번 탭·길게 누르기 없이 모든 기능 사용, 화면 전환 연출 0.3초 이하 |
| AC-13 | 읽어 주기 (P2) | 요청 카드·해설을 기기 TTS로 읽어 주는 버튼. 기술 검증 후 범위 결정 |
| AC-10 | 스크린 리더 (P2) | Unity 6에서 제공하는 모바일 스크린 리더 연동 기능(TalkBack/VoiceOver)의 적용 범위를 기술 검증 후 결정. 최소 목표: 메뉴·판정 버튼·문서 필드에 읽기 라벨 제공 |
| AC-11 | 한 손 조작 | 판정 패널·도구 바를 화면 하단에 배치해 엄지 손가락 영역 안에서 핵심 조작 가능 |

## 11.7 이용자 보호 (전연령, 아동 보호 기준 유지)

> 전연령으로 넓혀도 **가장 엄격한 기준(아동 보호)** 을 그대로 적용한다. 나이를 묻지 않으므로 누가 플레이하든 같은 보호를 받는다.

| ID | 요구사항 | 설계 상세 |
|---|---|---|
| CP-01 | 실제 개인정보 입력 없음 | 닉네임은 프리셋 조합만, 자유 텍스트 입력 필드가 게임 전체에 없음. **나이·생년월일도 묻지 않는다** |
| CP-02 | 가상 데이터만 사용 | 이름·주소·계정·기관 모두 가상. 도메인 `.example`, 전화번호 `000-0000-xxxx` 형식 ([부록 C](10-appendix.md#c-가상-데이터-작성-원칙)) |
| CP-03 | 실존 사칭 금지 | 실존 인물·기관·서비스명·상표·로고를 쓰지 않음. 사례 검수 체크리스트로 확인 |
| CP-04 | 광고·결제 없음 | 광고 SDK·인앱 결제 모듈을 포함하지 않음 |
| CP-05 | 추적 없음 | 분석·광고 식별자·크래시 리포트 SDK를 포함하지 않음. Unity의 클라우드 분석 서비스 비활성화 및 빌드 설정에서 관련 패키지 제거 확인 |
| CP-06 | 네트워크 없음 | 기본 빌드는 인터넷 접근이 필요 없도록 구성. Android Player Settings의 Internet Access를 'Auto'로 두고 네트워크 API를 쓰지 않으며, 빌드된 매니페스트에 불필요한 권한(INTERNET 포함)이 들어가지 않았는지 빌드 후 확인 |
| CP-07 | 외부 링크 | 게임 안에 외부 웹 링크 없음. 개인정보 처리 안내·라이선스는 앱 내부 화면으로 제공 |
| CP-08 | 공포 유발 금지 | 피해 장면 묘사 없음, 위협적 효과음·붉은 경고 화면 없음, 악역 캐릭터 없음 |
| CP-09 | 스토어 정책 | 출시 시 Google Play '가족' 정책과 Apple 앱 심사 지침의 아동 카테고리 요건을 최신 기준으로 재확인 (정책은 변경될 수 있으므로 출시 단계에서 검토) |
| CP-10 | 사용성 테스트 윤리 | 대상 연령 테스트는 보호자 동의·교사 입회하에 진행하고, 영상·음성 녹화 없이 관찰 기록만 남김 |
| CP-11 | 세대 존중 | 특정 세대를 '잘 속는 사람'으로 묘사하지 않는다. 사칭 사례의 요청자는 여러 세대에 고르게 배치한다 |
| CP-12 | 금융 정보 미사용 | 카드 번호·계좌 번호처럼 보이는 숫자를 문서에 쓰지 않는다. 필요하면 "카드 사진을 보내 달라" 같은 *요구 문장*만 쓰고 숫자는 넣지 않는다 |
