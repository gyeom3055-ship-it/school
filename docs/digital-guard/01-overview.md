## 1. 게임 개요와 핵심 재미

### 1.1 한 줄 콘셉트

> **"서류 속 작은 차이를 찾아내는 눈이, 우리 동네의 디지털 안전을 지킨다."**
> 디지털 안전 센터의 심사관이 되어 메시지·파일·계정 요청을 대조하고 판정하는 *규칙 기반 추리 퍼즐*.

### 1.2 영감과 독창성

《Papers, Please》에서 **장르적 메커니즘**(문서 검토, 정보 대조, 규칙 기반 판정, 날마다 늘어나는 규칙)만 참고하고, 그 밖의 요소는 모두 새로 설계한다.

| 구분 | 참고한 것 (장르 메커니즘) | DIGITAL GUARD의 독자적 설계 |
|---|---|---|
| 세계관 | — | 현대의 가상 도시 *누리시*. 학교·도서관·게임·택배·쇼핑·민원 등 모든 세대의 일상 디지털 공간 |
| 분위기 | — | 따뜻하고 밝은 협업 분위기. 억압·감시·도덕적 공포 요소 없음 |
| 플레이어 역할 | 문서를 심사하는 사람 | *사람들을 돕는* 심사관. 거부도 "안내와 보호"로 표현 |
| 판정 | 통과 / 거절 | **승인 · 거부 · 추가 확인** 3종. 사례마다 필요한 선택지만 노출. 거부 뒤에는 **신고 여부**까지 판단 |
| 핵심 도구 | 문서 대조 | **단서 칩**(두 정보를 대조해 생성), **의심 깃발**, **근거 트레이**, **내 기록 탭**, **자료 조회**, **공식 경로 확인** |
| 평가 | 실수 시 벌금·가족 위기 | **안전 게이지 + 편의 게이지**의 균형. 실패 페널티 최소화, 힌트 후 재도전 |
| 목표 | 생존 | 디지털 안전 습관 *학습과 숙달* (주제별 숙달도) |
| 그래픽 | — | 2D 도트 보안 센터(기본 시안) / 모던 미니멀(대체 테마) — 모두 독자 디자인 |

### 1.3 핵심 재미 (Fun Pillars)

| 재미 기둥 | 플레이어가 느끼는 감정 | 이를 만드는 장치 | 실제 플레이 예시 |
|---|---|---|---|
| **① 발견의 쾌감** | "찾았다!" | 돋보기 대조 → 불일치 시 *단서 칩*이 '톡' 튀어나오는 연출 | 문자의 링크 `kongkong-delivery.example`과 공식 목록 `kongkong.example`을 대조하자 "! 도메인 불일치" 칩이 생긴다 |
| **② 숙련의 성장감** | "이제 한눈에 보여" | 규칙이 하루 1개씩 늘고, 이전 규칙이 섞여 나옴. 주제별 숙달 배지 | Day 1엔 이름 비교만 했지만 Day 14에는 공유 범위·파일 내용·권한을 동시에 본다 |
| **③ 균형 잡기의 긴장** | "막기만 하면 안 되는구나" | 안전 게이지 + 편의 게이지. 과잉 차단 시 "모둠 과제를 못 냈어요" 같은 이야기 결과 | 처음 보는 `.zip` 파일이지만 내용물이 가족 사진뿐 → 승인하는 것이 정답 |
| **④ 도움의 보람** | "내 판단 덕분에 가족이 안전해졌어" | 반복 등장 인물, 판정 후 짧은 후일담 카드 | 은솔이의 할머니가 "손녀인 척한 문자에 안 속았어요!"라는 감사 메시지를 보낸다 |
| **⑤ 탐구의 자유** | "다시 해 보고 싶어" | 복습 노트, 연습실, 별 3개 도전, 보안 사전·확장자 도감 수집 | 틀렸던 사례를 복습 노트에서 다시 풀어 별을 올린다 |

### 1.4 1회 플레이 감각 (Day 5 예시, 약 12분)

1. 센터에 출근하면 AI 조수 **도트**가 "오늘의 소식: 누리시에 '택배 주소가 잘못됐다'는 가짜 문자가 돌고 있대요"라고 알려 준다.
2. **아침 브리핑**에서 새 규칙 카드 *R-LINK-01 "링크 주소는 공식 도메인 목록과 맞춰 보기"*를 읽고, 예시 2개로 미니 연습을 한다. 이 카드는 **오늘의 조건 띠**가 되어 검토 데스크 맨 위에 계속 붙어 있다.
3. **검토 데스크**에서 6건의 사례를 처리한다. 첫 사례는 진짜 배송 알림(승인), 두 번째는 가짜 택배 문자(거부 → 신고)다.
4. 한 건을 틀리자 "링크 주소를 '끝에서부터' 읽어 볼까요?"라는 힌트가 나오고, 다시 판단해 맞힌다.
5. **일일 리포트**에서 정확도 83%, 위험 탐지율 90%, 과잉 차단 0건, 별 2개를 받는다. 새 도구 *기기 기록 조회*가 Day 7에 열린다는 예고를 본다.

## 2. 대상 연령과 교육 목표

### 2.1 대상과 페르소나

| 구분 | 내용 |
|---|---|
| 대상 | **전연령** (전체 이용가). 혼자 읽고 플레이하는 기준은 만 10세 이상, 그보다 어린 이용자는 보호자와 함께 플레이 |
| 핵심 세그먼트 | ① 어린이·청소년 — 학습 플랫폼·게임·메신저 ② 청년·직장인 — 택배·쇼핑·중고거래·업무 파일 ③ 중장년·어르신 — 가족 사칭 메신저·민원·택배 문자 |
| 교육 채널 | 학교 수업, **공공도서관·복지관의 디지털 리터러시 프로그램**, 가정(세대가 함께 플레이) |
| 목표 이용 등급 | 전체 이용가 (폭력·공포·도박 요소 없음) |
| 1회 플레이 길이 | 하루(Day) 1개 = 10~15분. 수업·프로그램 1회(40~50분) 안에서 브리핑 + 1~2일 + 토론 가능 |
| 세대별 지원 | **플레이 모드**(차근차근/표준/도전, [7.8](04-levels-and-scoring.md#78-플레이-모드-전연령-지원)), 글자 크기 5단계(최대 175%), 쉬운 문장 |

**페르소나 A — "지민 (중1, 13세)"**
- 학습 플랫폼과 게임 앱을 매일 사용. 친구가 보낸 링크는 의심 없이 누른다.
- 텍스트가 길면 금방 지루해한다 → *짧은 문장, 시각적 강조, 즉각적인 피드백*이 필요.
- 니즈: "잘하고 있다"는 확인, 친구에게 자랑할 수 있는 성취(별·배지).

**페르소나 B — "하늘 (27세, 회사원)"**
- 하루에도 택배·쇼핑·카드 알림 문자를 여러 통 받는다. 바쁠 때는 링크부터 누른다.
- 업무 메일로 받은 압축 파일·문서 파일을 자주 연다. 어떤 확장자가 위험한지는 잘 모른다.
- 니즈: 출퇴근길 10분 안에 끝나는 짧은 플레이, 실생활에 바로 쓰는 판단 기준.

**페르소나 C — "박영순 (68세, 은솔이의 할머니)"**
- 메신저로 손주들과 연락한다. "폰이 고장 났다"는 가족 메시지에 쉽게 마음이 흔들린다.
- 작은 글자와 빠른 화면 전환이 어렵다 → *큰 글자, 차근차근 모드, 시간 제한 없음*이 필요.
- 니즈: 손주와 같이 해 볼 수 있는 게임, 겁주지 않는 설명.

**페르소나 D — "오 사서 (공공도서관 디지털 리터러시 프로그램 담당)" / "서 선생님 (중학교 정보 교사)"**
- 프로그램이나 수업에 쓸 *광고 없는 오프라인 교육 콘텐츠*를 찾는다. 참여자 나이가 섞여 있는 경우가 많다.
- 니즈: 한 회차 분량으로 끊어 쓰기, 학습 목표가 명확한 구성, 참여자가 무엇을 틀렸는지 설명할 수 있는 해설, 세대가 함께 이야기할 거리.
- 참고: 교사·사서용 대시보드나 참여자 관리 기능은 기본 기획에 포함하지 않는다(데이터 수집 금지 원칙). 대신 *활용 가이드 문서*를 별도 제공하는 것을 로드맵 P2로 둔다.

모든 목표는 "플레이어는 ~할 수 있다" 형태로 작성하고, 게임 안에서 해당 행동을 *관찰 가능한 판정*으로 확인한다.

|---|---|---|---|---|
| E1 | 개인정보 최소 수집 | 서비스 목적에 필요한 정보와 불필요한 정보를 구분한다 | 신청 양식에서 불필요한 항목에 깃발 표시 | Day 2 |
| E2 | 비밀번호 보안 | 이름·생일 등 추측하기 쉬운 정보가 들어간 비밀번호를 알아본다 | 프로필과 비밀번호 점검표 대조 | Day 3 |
| E3 | 다중 인증 | 인증 코드는 본인만 사용하며, 내가 시도하지 않은 인증 요청은 거절해야 함을 설명한다 | 인증 요청 알림 + 활동 기록 대조, 인증 코드 요구 메시지 거부 | Day 11 |

| E8 | 로그인 알림·기기 | 로그인 알림의 기기·시간·장소를 자신의 활동과 맞춰 본다 | 로그인 알림과 시간표·기기 목록 대조 | Day 7 |
| E9 | 디지털 발자국 | 공개 프로필·게시물에서 위치·일정·신원을 드러내는 정보를 찾아낸다 | 공개 프로필 항목 검토 | Day 12 |

**교육과정·프로그램 연계(참고):** 2022 개정 교육과정 중학교 *정보* 과목의 '디지털 문화' 영역과 초등 실과 정보 단원의 수업 보조 자료로, 그리고 공공도서관·복지관의 성인·어르신 디지털 리터러시 프로그램 교재로 쓸 수 있도록 설계한다. 성취기준 코드 매핑과 프로그램별 운영안은 협력 교사·사서와 검토한 뒤 활용 가이드에 싣는다(현재 미확정).

### 2.3 교육 방침

- **공격 방법은 가르치지 않는다.** 비밀번호 추측법, 계정 침입, 피싱 메시지 제작 방법 등은 다루지 않는다. 모든 사례는 *발견 → 예방 → 대응* 관점에서만 구성한다.
- **공포 대신 행동 요령.** "해킹당하면 큰일 나요!"가 아니라 "이럴 땐 이렇게 하면 안전해요"로 설명한다.
- **정상 사례도 충분히.** 전체 사례 중 약 40%는 *승인이 정답인 정상 요청*으로 구성한다. 첨부 파일·처음 보는 기기·긴급 공지처럼 *겉보기엔 낯설지만 위험하지 않은* 사례를 일부러 섞어 '의심부터 하고 막기' 습관을 만들지 않는다.
- **정답을 알려 주는 문장은 넣지 않는다.** 문서 안에 "답장할 필요 없어요", "이건 안전한 메시지예요"처럼 판정을 대신해 주는 문장을 쓰지 않는다. 판단은 플레이어가 자료를 대조해서 내린다([10.7](06-unity-architecture.md#107-데이터-검증-에디터--ci) 검증 규칙).
- **세대를 탓하지 않는다.** "어르신이 잘 속는다" 같은 표현을 쓰지 않는다. 사칭 문자는 *누구나* 받을 수 있는 것으로 다룬다.

## 3. 세계관 및 주요 게임 루프

### 3.1 세계관

**누리시**는 학교·도서관·가게·택배·민원이 모두 디지털로 연결된 가상의 현대 도시다. 아이부터 어르신까지 누구나 디지털 서비스를 편리하게 쓰지만, 그만큼 사칭 문자·계정 도용·개인정보 노출 같은 문제도 생긴다. 누리시는 이를 돕기 위해 **누리 디지털 안전 센터**를 세우고, 시민 누구나 지원할 수 있는 *디지털 안전 심사관*을 모집했다. 플레이어는 이번에 새로 들어온 심사관이다.

> 모든 장소·서비스·인물·주소는 게임용 가상 데이터이며, 실존 기관·서비스·인물과 무관하다. 가상 데이터 작성 원칙은 [부록 C](10-appendix.md#c-가상-데이터-작성-원칙) 참고.

#### 주요 디지털 공간 (가상)

### 3.2 주요 게임 루프

#### (1) 사례 루프 — 1건당 1~3분

```
 ⓪ 오늘의 조건 띠 (데스크 맨 위에 항상 표시, 탭하면 규칙 카드 전체 보기)
 ┌──────────────┐   ┌────────────────────┐   ┌──────────────────┐   ┌──────────────┐
 │① 요청 도착     │──▶│② 자료 살펴보기       │──▶│③ 대조·의심 표시    │──▶│④ (필요시)      │
 │ 요청 카드 표시  │   │ 문서 탭 + 내 기록 탭 │   │ 단서 칩·깃발 생성  │   │  자료 조회     │
 └──────────────┘   └────────────────────┘   └──────────────────┘   └──────┬───────┘
                                                                            │
          ┌───────────────────────────────────────────────────────────────┘
          ▼
 ┌────────────────────────┐
 │⑤ 판정                    │
 │ 승인 / 거부 / 추가 확인   │── 추가 확인 ──▶ 확인 경로 선택 ──▶ 확인 결과 카드 ──▶ (2단계 사례면 ⑤로 다시)
 │ (+근거 선택: 고급 이상)   │
 └───────┬────────────────┘
         │ 거부
         ├────────▶ ⑤-1 신고할까요? [신고하기] [안내만 하기]
         ▼
 ┌────────────────────────┐        ┌─────────────────────────────┐
 │⑥ 결과 처리               │─오답──▶│ 1차: 힌트 → 다시 생각하기     │──▶ ⑤
 │ 정답 / 허용 대안 / 오답   │        │ 2차: 정답 공개 + 복습 노트 저장 │
 └───────┬────────────────┘        └─────────────────────────────┘
         ▼
 ┌────────────────────────┐   ┌──────────────────┐
 │⑦ 해설·후일담·점수        │──▶│⑧ 다음 사례 / 리포트 │
 └────────────────────────┘   └──────────────────┘
```

| 단계 | 화면 동작 예시 |
|---|---|
| ⓪ 오늘의 조건 띠 | 아침 브리핑에서 배운 규칙이 데스크 맨 위에 한 줄로 붙어 있다. "오늘의 조건: 링크 주소는 끝부분을 공식 목록과 비교해요" — 탭하면 규칙 카드(좋은 예·나쁜 예 포함)가 바텀 시트로 열린다 |
| ① 요청 도착 | 데스크 상단에 요청 카드가 미끄러져 들어온다. "박영순 님이 '택배 주소가 잘못됐다'는 문자를 받고 문의했어요." |
| ② 자료 살펴보기 | 문서 트레이에 *받은 문자*, *공식 연락처 목록*, 그리고 항상 있는 **내 기록**(요청자의 주문 내역·저장된 연락처·신청 내역) 탭. 탭하면 문서 뷰어로 펼쳐진다 |
| ③ 대조·의심 표시 | 🔍 대조 도구를 켜고 문자의 링크와 공식 목록의 도메인을 차례로 탭 → "! 불일치" 단서 칩 생성. 의심 필드에 🚩 깃발 |
| ④ 자료 조회 | (Day 7 이후) "📂 자료 조회" 버튼으로 등록 기기 목록·공식 연락처 등 센터 자료를 트레이에 추가한다. 첨부 파일은 **열 수 없고**, "파일 정보 보기"로 이름·종류·크기·압축 내용 목록만 확인한다 |
| ⑤ 판정 | 하단 판정 패널에서 승인/거부/추가 확인 중 하나를 누르고 확인 시트에서 확정. 고급 단계부터는 근거 1~3개를 함께 제출. 추가 확인이면 *누구에게 어떤 경로로* 확인할지 고른다 |
| ⑤-1 신고 | 거부를 확정하면 "신고도 할까요?"가 이어진다. 사칭·피싱이면 신고가 정답, 약한 비밀번호처럼 *다시 하도록 안내할 일*이면 '안내만 하기'가 정답(틀려도 감점 없이 해설에서 안내) |
| ⑥ 결과 처리 | 정답 → 해설. 허용 대안 → 부분 점수와 "더 좋은 선택" 해설. 1차 오답 → 힌트 후 다시 생각하기. 2차 오답 → 정답 공개 |
| ⑦ 해설·후일담 | 위험 위치 하이라이트 + 해설 2~4문장 + 실천 팁 + 요청자 후일담 + 획득 점수 |
| ⑧ 다음 사례 | 진행 상황 자동 저장 후 다음 요청 카드 등장. 마지막 사례 뒤에는 일일 리포트 |

#### (2) 하루 루프 — 10~15분

```
센터 로비 → 오늘의 소식 → 아침 브리핑(새 규칙 학습·미니 연습 → 오늘의 조건 지정) → 사례 4~8건 → 일일 리포트 → 해금/센터 꾸미기 → 로비
```

- **오늘의 소식**: 그날 등장할 위험 유형을 이야기로 예고한다(예: "블록타운에서 운영자를 사칭한 메시지가 늘고 있어요").
- **아침 브리핑**: 새 규칙이 있는 날에는 규칙 카드 → 좋은 예/나쁜 예 → 정답이 공개된 미니 연습 1~2문제(점수 없음). 새 규칙이 없는 날(복습 Day)에도 그날 집중할 **오늘의 조건**을 한 장 보여 준다.
- **일일 리포트**: 정확도, 위험 탐지율, 근거 확인율, 과잉 차단/위험 승인 건수, 신고 판단, 안전·편의 게이지, 별점, 시민 후일담, *처음 풀었을 때와 다시 풀었을 때의 비교*(복습한 사례가 있을 때).

#### (3) 장기 루프 — 전체 약 6~7시간

```
Day 진행 → 규칙·도구 해금 → 주제별 숙달도 상승 → 장 승급(견습 → 정식 → 선임 → 책임)
   ↘ 복습 노트 / 연습실 / 별 3개 도전 / 보안 사전·확장자 도감 수집 ↗
```

- 다음 Day는 **하루를 끝까지 마치기만 하면(별 1개) 열린다.** 별 개수로 진행을 막지 않는다.
- 별은 센터 꾸미기 아이템(게임 내 재화 없음, 별 누적 수로 해금)과 도전 과제에만 쓰인다.

### 3.3 게임플레이 단계 점검 (v0.2)

v0.1의 사례 루프를 처음부터 끝까지 따라가며 *정의되지 않은 흐름*, *헷갈리는 용어*, *정답이 새는 구멍*을 찾아 보완했다.

| # | 점검 항목 | v0.1의 문제 | v0.2 보완 |
|---|---|---|---|
| G1 | 오늘의 조건 | 브리핑에서 배운 규칙을 플레이 중에 다시 보려면 규칙집을 열어야 했다 | 데스크 맨 위 **오늘의 조건 띠** 추가. 탭하면 규칙 카드 전체를 바텀 시트로 연다(S04 ⓪) |
| G2 | 용어 혼동 | 도구 '➕ 추가 확인'과 판정 '추가 확인'의 이름이 같았다 | 도구 이름을 **📂 자료 조회**로 바꾼다. '추가 확인'은 판정에만 쓴다 |
| G3 | 비교 기준 부족 | 가족·택배 사칭처럼 *요청자 본인의 기록*과 비교해야 하는 사례를 담을 자리가 없었다 | 모든 사례에 **내 기록 탭**(주문 내역·저장된 연락처·신청 내역·내가 요청한 파일)을 둔다. 메시지가 *주장하는 것*과 내가 *원래 아는 것*을 나눠 보여 준다 |
| G4 | 1단계 추가 확인의 결말 | 추가 확인이 정답인 1단계 사례(C4-01)에서 플레이어가 확인 결과를 보는지 정해지지 않았다 | 추가 확인 정답이면 **확인 결과 카드**를 반드시 보여 준다. 1단계 사례는 결과 카드 + 해설로 끝나고, 2단계 사례는 결과 문서가 추가된 채 다음 단계로 간다 |
| G5 | 잘못 고른 추가 확인 | 자료만으로 판단할 수 있는데 추가 확인을 고른 경우의 처리가 없었다 | 허용 대안으로 지정되지 않았다면 1차 오답으로 처리하고 힌트 "필요한 정보가 이미 자료 안에 있어요"를 보여 준다 |
| G6 | 확인 경로 오답 | 판정은 맞았는데 경로를 잘못 고르면 어떻게 되는지 불분명했다 | 경로만 **한 번 더 고르게** 한다. 판정 점수는 유지, 경로 점수는 0. 두 번째도 틀리면 올바른 경로를 보여 주고 진행한다(사례가 막히지 않게) |
| G7 | 신고 | '거부+신고'가 자동 연출이라 신고 판단을 배우지 못했다 | 거부 확정 후 **신고할까요?** 단계 추가. 정답 +10점, 틀려도 감점 없음 |
| G8 | 근거만 틀린 경우 | 판정은 맞고 근거가 틀린 경우 재도전 여부가 불분명했다 | 재도전 없음. 해설에서 올바른 근거를 체크 표시로 보여 주고 근거 점수만 0 |
| G9 | 정답 보기 | '정답 보기'를 고른 경우 연속 정답 처리가 없었다 | 2차 오답과 같이 처리(연속 정답 0, 복습 노트 저장) |
| G10 | 다시 생각하기 범위 | 재도전 때 무엇을 바꿀 수 있는지 불분명했다 | 깃발·단서·근거 모두 다시 바꿀 수 있다. 문서와 스크롤 위치는 유지 |
| G11 | 확인 없이 판정 | 자료를 하나도 열지 않고 판정할 수 있었다 | 허용한다(강제 없음). 근거 확인 점수만 없고, 3번 연속이면 도트가 "자료를 열어 보면 단서를 찾기 쉬워요"를 1회 안내 |
| G12 | 첨부 파일 | 파일을 '연다'는 행동이 정의되지 않았다 | 게임 안에서 파일은 **열리지 않는다**. "파일 정보 보기"로 이름·확장자·종류·크기·(압축이면) 내용 목록만 본다 |
| G13 | 정답이 새는 문장 | 정상 메시지에 "답장할 필요는 없어요" 같은 문장이 들어가면 판단할 거리가 사라진다 | 정답 암시 문장 금지 원칙과 검증기 경고 추가([10.7](06-unity-architecture.md#107-데이터-검증-에디터--ci)) |
