### 13.3 제작 로드맵

> 아래 기간은 **소규모 팀(기획 1, 프로그래밍 1~2, 아트 1, 파트타임 사운드)** 을 가정한 *추정치*다. 팀 규모·숙련도에 따라 Phase 0 종료 시 다시 산정한다.

| Phase | 기간(추정) | 목표 | 주요 작업 | 완료 조건 (마일스톤) |
|---|---|---|---|---|
| **0. 프리프로덕션** | 3주 | 재미·기술 검증 | 종이 프로토타입(카드 문서로 사례 10개 플레이 테스트), UI Toolkit vs uGUI 기술 검증(픽셀 글꼴 선명도, 핀치 확대, 저사양 기기 성능), 데이터 스키마 확정 | 종이 테스트에서 참가자 과반이 "다음 사례를 더 하고 싶다"고 답함 / UI 기술 결정 문서 / 스키마 v1 |
| **1. 수직 슬라이스** | 6주 | 핵심 루프 완성 | Core(RuleEvaluator·Session·Score), 검토 데스크·대조·표시·판정·해설, 브리핑, 일일 리포트, 저장(P0), 모던 테마, CaseValidator(오류), Day 0~3 사례 약 20개 | 처음부터 끝까지 Day 0~3 플레이 가능, 판정기 단위 테스트 통과, 대상 연령 5명 이상 사용성 테스트 1차 |
| **2. 알파** | 8주 | 2장까지 콘텐츠 + 학습 시스템 | Day 4~9, 추가 확인 판정·확인 경로, 추가 정보 조회 도구, 복습 노트, 용어 사전, 숙달도, 안전·편의 게이지, CSV 가져오기 도구 | Day 0~9 플레이 가능, 사용성 테스트 2차, 교사·사서 자문 1차 |
| **3. 도트 테마** | 4주 (알파와 일부 병행 가능) | 테마 교체 구조 검증 | 픽셀 아트·글꼴·9-slice·애니메이션, ThemeDefinition B, 테마 전환 중 상태 유지 | 같은 사례를 두 테마로 플레이 시 정보 동일(자동 스크린샷 비교 + 수동 확인) |
| **4. 베타** | 8주 | 전체 콘텐츠 + 접근성 | Day 10~18, 근거 선택, 2단계 사례, 엔딩, 연습실, 접근성 옵션(P1), 마이그레이션·부분 복구, 배경음 | 전체 플레이 가능, 판정 분포·난이도 밸런스 1차 조정, 디바이스 매트릭스 통과 |
| **5. 출시 준비** | 4주 | 품질·심사 | 버그 수정, 밸런스, 문장 검수, 스토어 등록 자료, 정책(가족·아동) 검토, 개인정보 처리 안내 | 14.4 출시 완료 기준 충족 |
| **6. 출시 후 (P2)** | — | 확장 | 템플릿 생성 사례, 시간 도전 모드, 꾸미기, 다크 모드, 스크린 리더, 교사용 가이드 | — |

총 약 33주(약 8개월, 병행 시 단축 가능)를 추정 범위로 둔다.

### 13.4 위험 요소와 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 텍스트가 많아 어린 이용자가 지루해하거나 어르신이 읽기 힘들어함 | 핵심 재미 훼손 | Phase 0 종이 테스트에서 문서 길이 상한 결정, 필드 단위 시각화, 해설 4문장 제한, 차근차근 모드 |
| 픽셀 글꼴 가독성 부족 | 도트 테마 사용성 저하 | 문서 본문 일반 글꼴 옵션, 정수 배율 렌더, Phase 0 기술 검증 |
| 사례 제작 속도 부족(약 100개) | 일정 지연 | 사례 기획 시트 + 가져오기 도구, 검증기 자동화, 템플릿 재사용 |
| 정답 논란(애매한 사례) | 교육 신뢰도 하락 | 판정기 검산 + 교사·사서 자문 + 테스트에서 정답 동의율 낮은 사례 수정 (14.3) |
| 공포감 유발 | 교육 방침 위반 | 톤 가이드·금지 표현 검사, 테스트 후 감정 질문 |
| 플랫폼 정책 변경 | 출시 지연 | Phase 5에서 최신 정책 재검토 시간 확보 |

### 14.3 사용성·교육 효과 테스트

| ID | 테스트 | 방법 | 성공 기준 |
|---|---|---|---|
| UT-01 | 조작 이해 | 대상 연령 8~10명, Day 0 진행을 도움 없이 관찰 | 80% 이상이 도움 없이 첫 대조·판정 완료 |
| UT-02 | 텍스트 부담 | Day 5 플레이 후 "읽을 게 너무 많았나요?" 5점 척도 | 평균 3.0 이하 (5 = 매우 많음) |
| UT-03 | 정답 동의율 | 각 사례를 테스트한 뒤 해설을 보고 "이 정답이 이해되나요?" | 사례별 80% 이상, 미달 사례는 수정 |
| UT-04 | 감정 확인 | 플레이 후 "무섭거나 불안했나요?" | "그렇다" 응답 10% 미만 |
| UT-05 | 학습 효과(사전·사후) | 게임 밖 종이 퀴즈 10문항(가상 메시지·공유 설정 판단)을 플레이 전후 실시 | 사후 평균 정답률이 사전보다 상승. 특히 *정상 사례 승인* 문항에서 과잉 거부 감소 |
| UT-06 | 재미 | "다음 날 근무를 계속하고 싶나요?" | 70% 이상 "그렇다" |
| UT-07 | 교사·사서 검토 | 교사 2명 이상, 사서 1명 이상 자문 | 사실 오류·부적절 표현 지적 사항 전부 반영 |
| UT-08 | 세대별 사용성 | 청소년·청년·어르신 각 5명 이상, 같은 Day를 각자 고른 모드로 플레이 | 세대별 완주율 80% 이상, 어르신 그룹에서 "글자가 작다"는 응답 20% 미만 |
| UT-09 | 세대 함께 플레이 | 조부모·손주 짝 3팀 이상이 한 기기로 Day 1개 | 플레이 후 "같이 이야기할 거리가 생겼다" 응답 과반 |

> 테스트는 보호자 동의·교사 입회하에 진행하고, 이름 등 개인정보 없이 익명 번호로만 기록한다(CP-10). 퀴즈 결과는 종이로 수집하고 게임은 어떤 데이터도 수집하지 않는다.

### 14.5 완료 기준 (Definition of Done)

**기능 단위 완료 기준** — 모든 기능은 아래를 만족해야 "완료"로 표시한다.

1. 기획서의 해당 요구사항(ID)을 모두 구현하고, 관련 자동/수동 테스트를 통과했다.
2. 모던 테마에서 동작하고, P1 이후에는 도트 테마에서도 동작한다(테마별 로직 분기 없음).
3. 글자 크기 150%, 360×640dp에서 레이아웃이 깨지지 않는다.
4. 탭만으로 사용할 수 있다.
5. 화면 전환·앱 전환 후 상태가 유지된다.
6. 새 문자열은 String Table에 등록되고 문장 검수를 거쳤다.
7. 콘솔 오류·경고 없이 동작한다(개발 빌드 기준).

**사례 콘텐츠 완료 기준**

1. CaseValidator 오류 0건, 경고는 사유를 기록하고 승인받음.
2. 5.12 체크리스트 전 항목 통과.
3. 두 테마에서 실제 플레이로 확인.
4. 사용성 테스트를 거친 경우 정답 동의율 80% 이상.
